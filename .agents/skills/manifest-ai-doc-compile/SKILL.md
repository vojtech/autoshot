# Manifest AI Doc Compiler

Use this skill when initializing an AI optimization profile for a project, preparing a codebase for distribution to automated agent work-loops, or compiling modern `llms.txt` or `ai-context.md` project specifications.

## Execution Workflow
When triggered, follow this multi-step processing sequence to build the unified machine spec:

1. **Token Tree & Dictionary Mapping:** Locate global constants, design primitives, configurations, or system tokens. Output them at the top of the file as a flat, structural hierarchy mapping global definitions to their system wrappers.
2. **Boundary & Instruction Extraction:** Scan for project configurations (`.cursorrules`, environment definitions, system invariants) and extract core operational guardrails. Explicitly compile a list of "Forbidden Access Patterns."
3. **Public Interface Aggregation:** Crawl the workspace to identify all public entry points, modules, controllers, or interfaces. For each module found, extract:
    - The raw, fully-typed signature block.
    - The structural rules or injection requirements for parameters.
    - The inline consumption recipes generated by the `inline-ai-doc-encoder` skill.
4. **Consolidated Output Generation:** Write all extracted data out into a single, continuous text file named `ai-context.md` (or append to an existing `llms-full.txt` framework) at the root of the project.

## Document Structure Layout Rule
The output document must adhere strictly to these consecutive Markdown zones:
- `# AI Context: [Project Name]` -> Global metadata tracking project version and runtime dependencies.
- `## Section 1: Foundations & System Invariants` -> The structural configuration map and negative architectural boundaries.
- `## Section 2: Component & API Contracts` -> Flat blocks containing raw signatures and slot/dependency rules for every public module.
- `## Section 3: Reference Assembly Recipes` -> Hyper-dense layout blocks demonstrating how separate modular endpoints assemble into functional blocks.
